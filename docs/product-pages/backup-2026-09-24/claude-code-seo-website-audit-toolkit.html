Who this is for

Developers, technical marketers and agencies who own a website that exists and is not performing in search. It assumes you can read a diff, run a command, and reach the live site. It does not assume you are an SEO specialist — most of it is aimed at the competent generalist who has inherited responsibility for how a site does in search.

If you are building a site from nothing, the Claude Code Website Launch System is the better starting point. This toolkit is for the site you already have.

What it is for

The failure mode in agent-assisted SEO work is not bad advice. It is a check that reports success because it never actually ran, in a report that reads as authoritative. You get a confident list, act on it, and nothing changes — because the crawler stripped query strings and never saw page two, or the checker was pointed at the source rather than the built output, or the audit fixed the findings in the same run and left no report.

Every prompt in here is written against that. They demand evidence rather than summaries. They forbid fixing in the same run, because an audit whose findings disappear into a commit is not an audit. And they insist that every check is proved capable of failing before it is trusted.

What using it looks like

  1. Open START-HERE.md. It routes you to one file based on your situation.
  2. Open that prompt, replace the bracketed values, and hand it to Claude Code.
  3. It runs a discovery phase and changes nothing. You approve what it found.
  4. It produces findings with evidence — the URL, the response, the exact markup.
  5. You fix things, in a separate session, with the validation command it gave you.
  6. You break each check deliberately and confirm it goes red before trusting it.

What it does not do

It does not access Search Console, Bing or any analytics platform on your behalf — Claude Code has no credentials for your properties and cannot get them. Where a workflow needs that data, it tells you exactly what to export.

It does not promise a ranking. Nobody can. And where the honest conclusion about a site is that the constraint is authority rather than optimisation, these prompts are written to say so rather than supply a list of small changes that would not move anything.

Would rather have someone else do it once

This toolkit is the method, packaged for you to run. If what you want instead is an outside read of one site, the Website Launch & Conversion Review is a fixed-scope written report on up to five public pages — findings with evidence, no changes made, no guarantees. It takes requests, not bookings.

Inside the SEO & Website Audit Toolkit

  1. What lands in your inbox

    One ZIP. Fourteen numbered modules, twenty prompts, four report templates and three checklists, plus a START-HERE that tells you which file to open. All plain Markdown — nothing to install, no account, no subscription.

  02-on-page-seo/

  14-reporting/
  prompts/
  templates/

  2. START-HERE routes you in four minutes

    It does not explain SEO. It asks what your situation is and sends you to one file. The table is the whole page.

    | Your situation                  | Open this                                |
| Pages are not being indexed     | 03-indexation/INDEXATION-TROUBLESHOOTING |
| About to launch                 | 12-launch-validation/PRE-LAUNCH-SEO      |
| Traffic dropped after migrating | 12-launch-validation/MIGRATION-SEO       |

  3. Open the prompt, fill in the brackets

    Every prompt names its role, objective, discovery phase, constraints, evidence requirements, analysis, validation and deliverables. Replacing the bracketed values is the difference between a scoped audit and a generic one.

    You are a technical SEO specialist auditing [SITE], a
[SITE TYPE] built on [PLATFORM]. I own the codebase.

  4. Discovery runs first and changes nothing

    The agent reports the structure, fetches one URL of every type, and states what it cannot determine without data you have not given it. Then it stops and waits.

    Stop and show me this before continuing.

  5. Findings come with evidence, not summaries

    Every finding carries the URL, the response and the exact markup. The prompt forbids fixing anything in the same run — an audit whose findings disappear into a commit leaves you a diff and no report.

    - Do not change anything in this run.
- Every finding needs evidence: the URL,
  the response, the exact markup.

  6. Platform workflows carry what actually differs

    A Shopify sitemap cannot be hand-edited. A WordPress SEO plugin owns canonicals. An Astro site with no `site` in its config emits relative canonicals silently. Audits that do not know these produce confident wrong answers.

    11-platform-workflows/
  SHOPIFY.md
  WORDPRESS.md
  ASTRO.md
  STATIC-AND-CUSTOM.md

  7. Every check gets proved capable of failing

    Break the thing, watch the check go red, restore it, watch it go quiet. Both directions. This is the rule the whole toolkit is built on, because a check nobody has seen fail is a line in a log that says PASS.

    # add a noindexed URL to the sitemap copy
# run the checker -> must report a failure
# remove it -> must go quiet

  8. Hand someone the report

    Four templates: executive summary, technical findings, remediation backlog, and before-and-after. Each has an unmeasured section, because a report that hides its gaps reads as more complete and is less useful.

    14-reporting/
templates/EXECUTIVE-SUMMARY.md
templates/TECHNICAL-FINDINGS.md
templates/REMEDIATION-BACKLOG.md
templates/BEFORE-AFTER.md
