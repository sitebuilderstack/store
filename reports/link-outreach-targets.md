# Link outreach targets

Categories and criteria, not a contact list to work through. **Nothing here has
been contacted, and no automated outreach exists in this repository.** Building
one was explicitly out of scope, and adding it later should be a deliberate
decision rather than a consequence of this file existing.

## The precondition nobody wants to hear

**There is nothing to pitch yet.**

The benchmark has no results. The site is fourteen days into Search Console with
1,093 impressions. Outreach before the linkable asset exists produces one of two
outcomes: silence, or a link to a page that disappoints the person who followed
it — which is worse, because it spends a relationship that could have been used
once the data existed.

The order that works: run the benchmark, publish it, then approach people for
whom it is genuinely news. This file is written now so the criteria are set
before there is any temptation to loosen them.

## What actually earns a link here

Ranked by how likely each is to work for this site specifically.

| The free samples | Two complete workflows, ungated | Published |
| The free tools | Four browser-only tools, no email gate | Published |

The guides will not earn links on merit alone. There are thousands of "how to
use Claude Code" articles and no reason for anyone to link to another one. That
is the honest reason the benchmark exists.

## Categories, with the criterion that matters for each

### Claude Code and AI developer communities

Places where a benchmark of agent behaviour is on-topic rather than promotional.

- **Criterion:** does the community discuss tool behaviour and failure modes, or
  only announcements? Only the first is worth approaching.
- **Approach:** post the dataset and methodology, not the product page. If the
  post cannot stand with the store link removed, it is an advertisement.

### AI and developer newsletters

- **Criterion:** does the newsletter link to primary sources, or only to other
  newsletters? Check three back issues before writing.
- **Approach:** the finding, in two sentences, with the dataset URL. Editors
  need the number, not the narrative.

### Platform-specific developer publications

Shopify, WordPress, Astro, Next.js. Each has its own developer publications and
each will care about **its own row** in the benchmark rather than the comparison.

- **Criterion:** does the publication cover tooling critically, or only
  celebrate the platform? A per-platform result that is unflattering will not be
  published by the second kind, and pitching it there wastes both parties' time.
- **Approach:** lead with the platform's own result, including where it did
  badly. A pitch that only flatters is transparent.

### SEO publications

- **Criterion:** do they publish methodology, or only conclusions? This dataset
  is small, and a publication that will not print the caveats will misreport it.
- **Approach:** offer the caveats before they ask. The sample size is the first
  thing a good editor will challenge, and having it volunteered changes the
  conversation.

### Web performance and accessibility communities

The most demanding audience here, and the one whose links are worth most.

- **Criterion:** they will check the claims. Approach only when the accessibility
  caveat is stated on the page, because they will find it otherwise.
- **Note:** the benchmark's automated accessibility scores are a weak proxy and
  the page says so. Leading with them here would be a mistake; leading with the
  admission is not.

### Developer resource lists and awesome-lists

- **Criterion:** curated and maintained, or an unreviewed pull-request dumping
  ground? A link from the second is worth nothing and may be worse than nothing.
- **Approach:** the free samples and tools fit these better than the products do.

### GitHub

The public mirror is the natural home for the harness and dataset.

- **Criterion:** a repository someone could actually re-run. That is a real
  criterion for this project, not a formality — if the harness cannot be run by a
  stranger, no amount of outreach fixes it.

## Rules for any outreach that does happen

1. **No automation.** No scraped contacts, no templated mail merges, no
   sequences. One person writing to one person about one thing.
2. **The asset comes first.** If there is no result, there is no pitch.
3. **State the conflict.** This is published by a store selling Claude Code
   workflows. Anyone who finds that out later will discount everything else.
4. **No link exchanges, no paid links, no guest posts written for the link.**
   All three are against Google's spam policies, and the risk is asymmetric:
   the upside is a link, the downside is the whole domain.
5. **Take no for an answer the first time.** A second email to someone who did
   not reply is the point at which outreach becomes spam.

## What would tell you this is working

Referring domains from the benchmark, and whether they cite the dataset or only
the summary. A citation of the dataset means the methodology survived contact
with someone who checked it, which is a stronger signal than the link.

Not measurable yet, because there is nothing to measure.
